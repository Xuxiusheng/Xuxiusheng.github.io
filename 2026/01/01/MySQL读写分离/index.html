MySQL读写分离

概念

MySQL的读写分离架构是一主多从，一个主库负责处理读写，从库只负责读负载。

MySQL读写分离架构

主从复制流程

  1. 主库将数据库中数据的变化写入到 binlog
  2. 从库连接主库，建立长连接
  3. 从库会创建一个 I/O 线程向主库请求更新的 binlog
  4. 主库会创建一个 binlog dump 线程来发送 binlog ，从库中的 I/O 线程负责接收
  5. 从库的 I/O 线程将接收的 binlog 写入到 relay log 中。
  6. 从库的 SQL 线程读取 relay log 同步数据到本地（也就是再执行一遍 SQL）

从库同步主库数据的过程是串行化的，也就是说主库上并行的操作，在从库上会串行执行

如何避免主从数据不一致带来的影响

主从数据库之间的数据同步有一定的时差，数据不是实时一致的。那对于强一致性场景，如何避免主从不一致带来的影响呢？

  • 强制读主库：对于一致性要求高的，强制路由到主库
  • 同步写从库：主库和从库同步更新，高并发下性能非常差
  • 中间缓存：数据写入中间缓存，过期时间设置为最大同步时间

如何减小主从延迟时间

  • 尽量避免大事务：事务执行成功才能将binlog同步给从库，大事务不仅执行时间长，而且产生的binlog体积大，网络传输时间也长，导致严重的数据不一致窗口
  • 从库太多，导致主库写操作效率低，设置合理的从库数量
  • 从库硬件性能差或网络延迟高
  • 从库开启并行复制，并行重放不同库的日志，这是库级别的并行
