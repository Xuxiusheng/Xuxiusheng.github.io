Hello Agents-智能体范式

ReAct

在ReAct诞生之前，关于LLM的两大核心能力：推理能力(Reasoning)和行动能力(Acting)是被割裂研究的。推理能力，即模型推导出答案的思考过程；行动能力是模型调用外部工具解决问题的能力。在ReAct出现之前：

  • “推理”（Reasoning，如思维链 CoT）和“行动”（Acting，如与环境交互、调用工具）通常是分开研究的。
  • 单纯的推理容易陷入“黑盒”，导致幻觉（Hallucination）和错误累积；单纯的行动往往缺乏高层规划，难以处理复杂逻辑。

ReAct提出了一种协同机制：

  • 推理指导行动：通过自然语言推理来制定计划、跟踪进度、处理异常。
  • 行动辅助推理：通过与外部环境（如维基百科 API）交互获取真实信息，修正内部认知。

背景

  • 推理派（Reasoning）：以思维链（CoT）为代表，擅长通过生成中间步骤解决复杂逻辑问题，但完全依赖模型内部参数化知识。由于无法访问外部真实世界，容易产生“幻觉”，且一旦某一步推理错误，后续步骤会连锁出错（错误传播），且无法自我纠正。
  • 行动派（Acting）：以工具调用和环境交互为代表，擅长获取实时信息或执行操作，但往往缺乏深度的逻辑规划。缺乏高层逻辑指导，面对需要多步推导的复杂任务时，容易迷失方向或做出短视的决策。

ReAct的解决方案是边想边做，利用自然语言进行高层规划，利用行动获取的外部反馈来修正内部的推理轨迹

方法

ReAct机制很简单，将复杂的智能体行为简化为一个清晰的序列结构：Thought→
Action→Observation：

  • Thought (思考)：相当于人类的“内心独白”或“草稿纸”。它不仅仅是最终答案的铺垫，更是控制器。它负责拆解复杂问题、记录当前进度以及决定下一步该做什么。
  • Action (行动)：模型与外界的唯一接口。它可以是具体的函数调用（如 Search[query]）或环境指令。打破了模型知识的静态限制，使其能获取实时信息。
  • Observation (观察)：环境的反馈。这是连接“虚拟推理”与“现实世界”的桥梁。为下一轮的 Thought 提供事实依据，用于验证之前的假设或修正错误的计划。

ReAct局限性

  • 高度依赖LLM的自身的推理能力、指令遵循能力或格式化输出能力，如果输出格式不符，会导致整个流程中断
  • 执行效率低，每一次的Observation会被添加到上下文，需要多次调用 LLM，Token消耗量大
  • 整个机制的稳定运行建立在一个精心设计的提示词模板之上，如果提示词设计不当，效果会比较差
  • 存在局部最优风险，属于步进式决策，缺乏整体规划

Plan-and-Solve

ReAct 和 Plan-and-Solve 都是旨在提升大语言模型（LLM）解决复杂问题能力的提示工程（Prompt Engineering）范式，但它们的核心逻辑和适用场景有所不同。

  • ReAct边做边思考，每走一步都要观察环境再决定下一步，非常适合需要频繁与外部世界交互的任务。利用外部工具获取实时信息，解决模型幻觉问题
  • Plan-and-Solve是先整体规划将复杂任务分解为多个子任务，再根据规划依次执行子任务，适合纯逻辑推理或数学计算任务。主要依赖内部知识

Reflection

ReAct 和 Plan-and-Solve 范式中，智能体一旦完成了任务，其工作流程便告结束。然而，它们生成的初始答案，无论是行动轨迹还是最终结果，都可能存在谬误或有待改进之处。Reflection 机制的核心思想，正是为智能体引入一种事后的自我校正循环，使其能够像人类一样，审视自己的工作，发现不足，并进行迭代优化。

Reflection很简单，就是在ReAct或Plan-and-Solve基础上引入审查机制，模型输出答案后，对答案进行审查，检查是否有逻辑错误，并将检查结果作为反馈和输出答案一起作为新的上下文喂给模型进行修改。

Reflection是一种以成本换质量的做法，适合对最终结果的质量、准确性和可靠性有极高要求，且对任务完成的实时性要求相对宽松的场景
