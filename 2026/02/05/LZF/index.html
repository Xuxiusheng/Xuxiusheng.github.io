LZF压缩算法

基本原理

LZF(Lempel-Ziv-Free)压缩算法是一种快速、轻量级的无损数据压缩算法,设计目标是在压缩速度和压缩率之间取得良好平衡，特别适合对实时性要求较高的场景。Redis的quicklistNode压缩就采用了LZF算法。

LZF采用字典压缩思想：用“偏移量+长度”对重复出现的数据进行编码，从而减少冗余。

  • 核心思想：当一段数据之前出现过，只需记录：(1) 回溯距离(offset)；(2)匹配长度(length)

核心流程

  • 哈希函数：对当前处理的3字节（24位）数据计算哈希值（例如：((a << 8) ^ b) ^ c）。

  • 哈希表映射：哈希值作为索引，存储当前位置指针。当后续遇到相同哈希值的3字节序列时，可能表示重复模式出现。

  • 匹配成功时：记录匹配长度（最多允许8~255字节的匹配）,输出一个令牌（token），包含长度和偏移量信息,更新哈希表。

  • 匹配失败时：输出原始字节，并移动指针继续处理。

从上述流程可以看出，LZF的压缩数据由两种类型交替组成：

  • 字面量：未匹配的原始数据

  • 回溯引用：[长度, 偏移量]

示例

说了这么多理论性的东西，下面举个例子来说明一下这个算法：

压缩过程

输入数据

输入字符串："ABABABC"（字节数组形式）

位置 0 1 2 3 4 5 6
字节 A B A B A B C

第一步：初始化

  • 设置当前位置 ip = 0（指向 ‘A’）
  • 哈希表 htab[] 初始为空

第二步：处理位置0（ip=0）

  1. 取3字节："ABA"（位置0、1、2），即 A(0x41), B(0x42), A(0x41)
  2. 计算哈希值（简化示例）：
    • 假设哈希函数：hash = ((byte1 << 8) ^ byte2) ^ byte3
    • hash = ((0x41 << 8) ^ 0x42) ^ 0x41 → 假设得到哈希值 h1
  3. 查哈希表 htab[h1]：当前为空（无匹配）
  4. 无匹配时：
    • 将 htab[h1] = 0（记录当前位置0）
    • 输出字面量 'A'（位置0的字节）
    • 位置 ip 前进到 1

此时输出缓冲区：[A]

第三步：处理位置1（ip=1）

  1. 取3字节："BAB"（位置1、2、3） → B, A, B
  2. 计算哈希值 → 假设得到 h2
  3. 查哈希表 htab[h2]：为空（无匹配）
  4. 操作：
    • 将 htab[h2] = 1
    • 输出字面量 'B'
    • ip 前进到 2

此时输出缓冲区：[A, B]

第四步：处理位置2（ip=2）

这是关键匹配步骤：

  1. 取3字节："ABA"（位置2、3、4） → A, B, A
  2. 计算哈希值：与位置0的3字节相同，所以哈希值 h1
  3. 查哈希表 htab[h1] = 0（之前位置0存入的）
    • 注意：位置0的3字节 "ABA" 与当前位置的3字节 "ABA" 相同
  4. 验证是否真的匹配（防止哈希冲突），比较发现:
    • 位置0的 A = 位置2的 A
    • 位置0的 B = 位置3的 B
    • 位置0的 A（位置2）= 位置4的 A
    • 继续比较：
    • 位置1的 B = 位置3的 B
    • 位置2的 A = 位置4的 A
    • 位置3的 B = 位置5的 B
    • 匹配长度 = 4（从位置2开始的 "ABAB" 匹配位置0开始的 "ABAB"）
  5. 输出回溯引用：
  • offset（偏移量）= 当前匹配开始位置2 - 历史匹配位置0 = 2
  • length（长度）= 4
  • 将 (offset=2, length=4) 编码为token输出
  1. 更新哈希表：在匹配过程中，更新哈希表以加速后续匹配
  2. 移动位置：ip 前进 length = 4，即从位置2跳到位置6

此时输出缓冲区：[A, B, (2,4)]
（注意：实际输出是二进制编码，不是元组）

第五步：处理位置6（ip=6）

  1. 剩余字节 'C'，不够3字节（已到末尾）
  2. 直接输出字面量 'C'

最终输出：[A, B, (回溯引用:offset=2,length=4), C]

解压过程

解压器看到：

  1. 输出 'A' → 解压得到 "A"
  2. 输出 'B' → 解压得到 "AB"
  3. 遇到回溯引用 (offset=2, length=4)：
  • 从当前输出结果向前回溯2个字节
  • 复制长度4个字节
  • 具体过程：
  1. 输出 'C' → 最终 "ABABABC"
